## db設計手順

1. ドキュメント（ER図など）
   　　　↓
2. model
   　　　↓
3. migration
   　　　↓
4. db

## 設計にあたっての考え方

設計の大枠はドキュメントと差分が無いようにする（テーブル、リレーション、PK、FK）

modelでカラムの詳細要件を考える、modelの内容をそのままmigration、dbに反映させる。modelがdbの詳細設計書であるという考え方。

db設計・実装時はmodelを唯一の正とし、db反映後はdbを唯一の正とする。反映後にmodelやドキュメントがdbと差分が出た場合、model、ドキュメントを修正する。（db側が間違っていない場合）
