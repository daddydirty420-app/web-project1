# Todo運用

作業中に今回のタスクと無関係な問題を見つけた場合は、
その場では修正せずTodoとして記録する。

現在依頼されているタスク以外は変更しない。

適切な優先度フォルダに、新しいTodoファイルを作成する。

## 優先順位

- P0-critical
- P1-bug
- P2-refactor
- P3-techdebt
- P4-idea

## Todoの書き方

Todoファイルは、人が読むためのメモでもあるが、そのままCodexへ入力して実装を依頼できるMarkdownとして作成すること。

Todoファイル全体が実装依頼書になるように記述し、一部分だけをコピーすることを前提とした「実装プロンプト」や「Codexへそのまま渡せる実装プロンプト」の項目は作成しない。

Markdown全体をそのままCodexへ渡せば実装できる内容にすること。

## Todoに記載する内容

- タイトル
- 問題の概要
- 原因
- 修正方針
- 対象ファイル（必要な場合）
- 参照すべきファイル（必要な場合）
- 実装内容
- 実装時の注意事項

注：日本語で記載すること。
